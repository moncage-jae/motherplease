Chapter 02

조작 시스템

플레이어가 게임과 상호작용하는 유일한 수단을 정의합니다. 모든 입력은 왼손 하나의 움직임으로만 처리되며, 이 제약 자체가 게임의 핵심 공포 메커닉입니다.

핵심 원칙

2.3 상호작용 입력 — E키

마우스 휠 방식은 사용하지 않습니다. 오브젝트 상호작용은 E키로 통일합니다.

기획서 표기 범위

상호작용 키는 애초에 미니게임 안에서만 사용되며, 구체적인 상호작용 방식(콜리전 오버랩 여부, 판정 조건, 파라미터)은 미니게임마다 다릅니다. 실 접촉(콜리전 오버랩) 방식만 쓰는 것도 아닙니다. 이 기획서에는 "상호작용 키는 E로 통일한다"는 규칙만 남기고, 감지 범위·스크롤 방향·오브젝트 타입별 동작(PULL_PUSH/ROTATE/PRESS/WAVE/PLAYBACK) 같은 옛 휠 방식 전용 파라미터는 모두 제거했습니다. 개별 미니게임의 상호작용 방식은 각 미니게임 섹션(4장)에 기재합니다.

2.4 마우스 드래그 입력 — 시선 이동

화면을 드래그하면 시선(카메라)을 둘러볼 수 있습니다. 방향키(팔 이동)·E키(상호작용)와 별개의 세 번째 입력 채널입니다.

3.2 챕터 전환 연출 및 저장

시퀀스·다이얼로그 데이터 단위를 통합하는 다이얼로그(연출) 시스템을 개발 중입니다. 저장은 5장 체크포인트 시스템에서 정의하는 저장 지점(Save Point) 단위로 이루어지며, 실제 플로우 문서(10장)에 기록된 저장 시점을 그대로 따릅니다.

챕터가 클리어되면 챕터 클리어 분기 메뉴를 띄워 플레이어가 다음 챕터 계속 또는 메인 메뉴로를 선택합니다. 일반 진행과 챕터 선택 진행을 구분하지 않고 모든 챕터 클리어 시 동일하게 이 메뉴를 표시합니다(8장 UI). "다음 챕터 계속"을 선택하면 아래 전환 연출로 진행합니다.

각 미니게임은 개별적으로 설계·구현합니다. 4.1의 공통 구조는 게임플레이 로직을 강제하는 템플릿이 아니라, 체크포인트·세이브 연동을 위한 최소 공통 계약입니다. 모든 미니게임은 2장의 조작 시스템(방향키·E키·마우스 드래그)으로 플레이합니다.

게임플레이 로직(입력 처리·판정 조건·연출)을 미니게임마다 따로 만드는 것 자체는 문제 없습니다. 나비 시선 정렬형과 버튼 연타형처럼 장르가 전혀 다른 미니게임을 억지로 하나의 템플릿에 끼워 맞추면 오히려 코드가 복잡해집니다.

저장 지점(Save Point) 단위 자동 저장 및 복귀를 처리합니다. 저장 슬롯은 로컬 단일 파일 1개이며, 스타트 화면의 시작(이어하기 통합)과 챕터 선택 두 입구가 이 하나의 슬롯을 공유합니다.

8.3스타트 화면

게임 실행 시 가장 먼저 표시되는 화면입니다. 총 플레이타임은 상호작용 없이 표시만 합니다. 시작 버튼이 이어하기 기능을 겸합니다 — 별도의 이어하기 메뉴 항목은 없습니다.

요소기능조건
시작세이브 파일에 플레이 이력이 없으면 새 게임 시작, 플레이 이력이 있으면 그 저장 지점부터 이어서 진행. 확인 팝업 없이 즉시 분기 — 상세는 5.3항상 표시
챕터 선택도달·클리어한 챕터를 골라 그 챕터 처음부터 재생 — 상세는 8.5 챕터 선택 화면세이브 있고 클리어 챕터 1개 이상일 때만 활성화
옵션사운드·언어·화면 밝기 조정 및 초기화 팝업 표시 — 상세는 8.5 옵션 화면항상 표시
나가기클릭 시 8.6 나가기 확인 팝업 표시, '종료' 확정 시에만 게임 종료항상 표시
총 플레이타임total_playtime 값 표시 (시:분:초 형식)세이브 있을 때만 표시. 상호작용 없음.
검토필요 — 게임 전체 클리어 후 시작 버튼 동작

엔딩까지 모두 클리어한 상태에서 시작 버튼을 누르면 무엇이 실행되어야 하는지 [검토필요]. "이어할 진행"이 더 이상 없으므로 새 게임으로 처리할지, 마지막 저장 지점(엔딩 이후)으로 이어할지 결정이 필요합니다. 관련해서 8.8 화면 전환 플로우의 "마지막 챕터 클리어 후 처리" 노드도 함께 검토 대상입니다.
